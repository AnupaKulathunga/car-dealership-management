\section{Sprint Activities and Implementation}

\subsection{Development Environment Setup}

The team configured the development environment during the first two days of the sprint. This included initialising the monorepo structure with separate \texttt{client/} and \texttt{server/} directories, configuring TypeScript for both projects, and setting up the PostgreSQL database with Prisma ORM. Atlassian Jira was adopted to monitor tasks.

\begin{itemize}[leftmargin=1.5em, itemsep=4pt]
  \item Initialised React + Vite + TypeScript frontend with Tailwind CSS and shadcn/ui
  \item Set up Node.js + Express + TypeScript backend with ts-node-dev for hot reloading
  \item Configured Prisma schema and ran initial migration to create all database tables
  \item Created seed script with sample users, vehicles, and customers
  \item Configured ESLint + Prettier for consistent code formatting across the team
  \item Set up Git repository with feature branching strategy on GitHub and unified Git branches
  \item Scaffolded local containerization with Docker (PostgreSQL and pgAdmin)
\end{itemize}

\subsection{User Authentication System (US01)}

The system authentication has been fully realised. We engineered a secure, robust login paradigm driven by JSON Web Tokens (JWT) distributed via HTTP-only cookies. Passwords undergo rigorous, cryptographically secure hashing utilizing \texttt{bcrypt} before insertion into the PostgreSQL relational tier. Role-based access control (RBAC) definitions map user profiles directly to four operational groups (Admin, Manager, Sales Agent, Inventory Staff) enabling conditional route guards on the React Frontend (AuthContext Provider).

\subsection{Vehicle Inventory -- Add Vehicle (US02)}

Integration between the Client application and Backend database mapping inventory entries was successfully achieved. Administrators and Sales Agents have an interface to populate the \texttt{Vehicles} data entity via sophisticated form interfaces. Using \texttt{Zod} schemas on the frontend minimizes latency associated with request validation before hitting standard Express \texttt{POST} endpoints, enforcing strict integrity protocols over inputs (Make, Model, Year, VIN, Price).

\subsection{Vehicle Inventory -- View and Search (US03)}

An indexing overview grid was programmed onto the React components integrating shadcn/ui table designs. The view enables dynamic toggling between List and Grid interfaces. Extensive API route queries power the seamless pagination, textual cross-referencing capabilities, and filtering operations by fuel type, price, and operational status yielding high-performance vehicle tracking matching the specifications precisely. 

\subsection{Vehicle Inventory -- Edit Vehicle (US04)}

The backend REST endpoint (\texttt{PATCH}) for modifying vehicle records was completed. However, the frontend form integration encountered delays due to complex state management issues regarding image unlinking and concurrency handling. The basic text fields can be updated, but file handling edge cases caused this story to be somewhat delayed and carried over.

\subsection{Database Schema Implementation}

The database schema was implemented using Prisma ORM coupled with the PostgreSQL cloud container. The architecture mandates rigorous relational integrity encapsulating seven foundational entities: Users, Vehicles, Customers, Sales, Appointments, Invoices, and ActivityLog. Automated SQL migrations were standardized for local setups.

\subsection{Dashboard Layout}

A highly interactive foundational user interface layout was successfully accomplished. It features an adaptive and responsive sidebar navigation panel. Dynamic role-based visibility conditions securely display or shroud analytical dashboard components respectively based on the logged-in user profile, establishing a polished administration zone capable of tracking fleet performance statistics uniformly.

\section{Sprint Review}

\subsection{Completed Features}

\begin{itemize}[leftmargin=1.5em, itemsep=4pt]
  \item \textbf{User Authentication:} Secure login and registration with JWT tokens and role-based access control for four user roles (Admin, Manager, Sales Agent, Inventory Staff)
  \item \textbf{Vehicle Inventory:} Full CRUD operations for vehicle listings with search, filter, and pagination capabilities seamlessly mapping API definitions.
  \item \textbf{Dashboard Layout:} Responsive sidebar navigation bridging optimal user visibility and summary metrics securely via Role-Based Access Controls.
  \item \textbf{Database:} Complete schema with seven entities formulated alongside Prisma deployment structures resolving all foundational setups perfectly.
  \item \textbf{API Structure:} Standardised architecture resolving strict response standards coupled beautifully with robust Zod object checking paradigms.
\end{itemize}

\subsection{Incomplete / Carried Forward}

\begin{itemize}[leftmargin=1.5em, itemsep=4pt]
  \item \textbf{US04: Edit and update vehicle details:} The backend endpoints successfully support modification, but frontend edge cases with removing and updating vehicle images triggered state latency issues. This required pausing the UI integration for these edge cases. The remaining tasks are carried forward to Sprint 2.
\end{itemize}

\subsection{Demo Feedback}

Software presentation resulted in a complete confirmation of structural layout design specifications matching MoSCoW parameters. Evaluators validated the seamless integration of Postgres/Docker deployments alongside robust React-driven login portals gracefully avoiding monolithic blockages.

\section{Sprint Retrospective}

\subsection{What Went Well}

\begin{itemize}[leftmargin=1.5em, itemsep=4pt]
  \item Separation of the Frontend client and Backend systems early enabled swift, parallel component programming minimizing deadlocked hours.
  \item Using Prisma significantly streamlined database queries circumventing boilerplate coding redundancy entirely keeping efficiency very high.
  \item Jira synchronization tasks were accomplished autonomously with programmatic integration reflecting perfectly equal workload and point distribution amongst group resources matching constraints.
\end{itemize}

\subsection{What Could Be Improved}

\begin{itemize}[leftmargin=1.5em, itemsep=4pt]
  \item Establishing and detailing REST API interaction logic mapping even quicker could offset interface dependency hang-ups early during testing phase iterations.
  \item Time allocations explicitly mapped for final deployment-level Quality Assurance procedures required broader attention avoiding crunch-level merge operations at milestones.
\end{itemize}
